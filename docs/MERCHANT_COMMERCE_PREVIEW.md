# Merchant-controlled payment preview

This adds checkout creation and preparation, capability-scoped payment verification, saved merchant refund decisions, and a separate external-wallet refund handoff. The feature is off by default. It requires both `NOSTOS_MAINNET_OBSERVER_RECORD_CHECKS=yes` and `NOSTOS_MAINNET_COMMERCE_PREVIEW=yes` in the isolated SDK observer deployment. Hosted mainnet signing remains forbidden. Do not add hosted signer credentials.

Checkout uses the saved merchant observer destination, a fresh live synchronization check, a canonical Orchard return route and the exact saved order memo. A customer can supply the transaction ID from Noir or another wallet. The transaction ID is only a candidate; credit requires native account, amount, receiver, memo, pool and direction proof with three confirmations. The private checkout capability authorizes that record only. Noir's returned transaction ID now remains available for verification; manual verification also works after reopening the link.

A merchant decision does not send or reserve funds. Reviewing an approved refund creates the existing immutable instruction and reservation. The displayed fee ceiling is 10,000 zat. Continuing requires the NOSTOS account password and a current synchronization check. Only one handoff can be claimed. The returned ZIP 321 URI opens the merchant's own wallet; the merchant must verify its address, amount, memo and actual fee. NOSTOS cannot enforce a manually signed wallet fee. A higher fee leaves verification unresolved rather than falsely confirming it. Cancellation, a lost response or an uncertain wallet outcome never automatically releases the reservation or grants another handoff. Investigate the saved instruction and wallet history; do not resend.

After signing, save the refund transaction ID and check it. Binding a candidate does not mark a refund sent or confirmed. Only native owned-spend evidence with the saved fee ceiling can settle it. Partial refunds retain their original route; full refunds use the existing retirement journal. Session, verified email, origin, ownership, bounded attempts and strict fields protect the merchant routes.

The native decoder change accepts a shielded Orchard+Sapling display address and projects its validated Orchard receiver into a canonical single-receiver route. Unknown and transparent receivers remain rejected. It does not import Sapling viewing access. The installed old worker accepts only Orchard-only inputs; the native change must be built and tested on ARM64 before switching the preview.

## Build without switching services

`scripts/web/build-commerce-review.py --revision <exact-commit>` stages a fresh source directory under the existing private review, copies the previous ARM64 web dependencies, runs the full quality checks and web build in a separate container, and builds/tests a fresh pinned native source using the existing Cargo cache. It outputs a preserved worker copy, its SHA-256 and the exact source path. It never reads or rewrites runtime settings, wallet state, cookies, services or production mounts. No payment feature is enabled. A failed build leaves its directory for inspection; do not delete existing runtime data to retry.

The helper targets the operator's already established Ubuntu ARM64 build/review directories and Node image. It requires normal user 1001. Run only one native build at a time. The new Rust fixture test must pass on that host; this workspace has no Rust toolchain. Switching the broker binary requires a separate verified hash/config update and a normal drain/restart. Switching the isolated web container requires retaining its current runtime mounts and encryption key. Neither switch is performed by the builder.

## Evidence and remaining work

Local application tests include checkout preparation and capability proof, immutable return-route binding, missing feature flags, incomplete synchronization, ownership/injected-field rejection, decision idempotence, approval without RPC sends, password-bound one-time handoff, candidate-only binding and verified partial refund accounting. Existing record tests cover crash/reopen, fee/proof failures, full refunds and duplicate output claims. Browser tests use synthetic transport at phone and desktop sizes, including request creation, payment proof, mainnet receipt label, merchant approval, wallet review and saved refund confirmation. They never invoke a real wallet.

Still required: ARM64 native fixture/build success, isolated service installation and health checks, actual customer payment with exact memo, merchant receipt, actual merchant-wallet refund approval, native outgoing recovery, customer receipt/reopen, recovery checks, release review and demo. No successful build or synthetic proof establishes spending control or a funded round trip. Keep PR #8 in draft and production unchanged until those gates are evidenced.

## Resume after a pnpm launcher permission failure

The builder now installs its pinned pnpm launcher in a separate build-only tooling mount and invokes its CLI through Node. Nested package commands use that same tooling directory. The npm cache stays outside `/tmp` and outside the source tree. Failed build containers are preserved; retries use a unique container name.

The updated helper accepts `--resume --revision <original-source-commit>` only after checking the existing revision marker, source archive against the exact Git commit, and every archived source file. It refuses changed source, symlink substitutions or a workspace where native staging has already started. Download the updated helper separately; do not replace files inside the pinned staged source to repair its launcher. Runtime settings and wallet state are not needed for this retry.

If native tests stop because `NOSTOS_BACKUP_FIXTURE` is absent, use the updated helper with `--resume-native --revision <original-source-commit>`. It supplies the backup fixture path to both Cargo commands. Before resuming, it verifies the original staged archive and files, pinned native checkout and copied observer modules. Web checks are not repeated. All native tests must pass before the worker build and result report are produced.

## Install the verified private preview

`install-commerce-review.py` targets only the existing loopback preview and the operator-verified ARM64 build at c370ee2d0ec41a62eb7b2904d5f243bdea2424ca. It verifies the new worker hash eb6ccf6ec786b5867f8da84a881c1705fdf155ca5c69c84a6a82253b27e656e7, the existing worker/broker, the old preview container and its exact three mounts. Unexpected paths, changed credentials or an existing target container stop the procedure before a switch.

The installer retains the original broker config, worker binary, web environment and container. A separate private config points to the new worker and the same state directory. It drains the identified broker with SIGTERM, starts the replacement on loopback 38235, then switches only the private web container on loopback 3108. Existing product data, encryption key, RPC credentials and origins are reused. NOSTOS_MAINNET_COMMERCE_PREVIEW=yes is passed only to the new preview container. The original environment file is not rewritten. Signing stays in the external wallet, and installation requests no sends.

Success requires web sign-in HTTP 200, protected account and observer HTTP 401, and the mainnet network response with commerce enabled. A failed health check stops the replacement before restarting the prior broker and web container. No force stop is used for a broker that is still draining. Retain all stopped containers and configs for inspection and rollback. Current merchant sync readiness remains a separate authenticated check in Settings, followed by the explicitly reviewed funded payment/refund test.

The observer authentication health probe must POST to `/` without credentials. GET is rejected earlier with HTTP 403 by the broker's method policy; POST receives the expected HTTP 401 challenge. The installer uses POST for both replacement and rollback broker checks. A retry may reuse its existing private replacement config only when every value matches the verified replacement exactly; changed config is preserved and refused. The installer test suite includes a live local broker protocol check, without accessing any worker or wallet.
